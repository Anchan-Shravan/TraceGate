# A0 Gateway Implementation Plan

> **For agentic workers:** Follow this plan inline with the user, one small step at a time. Use test-first development and wait for the user's output before continuing.

**Goal:** Build a local pass-through gateway for Ollama `/api/chat` that preserves requests and responses and writes one JSONL trace record per request.

**Architecture:** FastAPI receives the runner's `/api/chat` request and forwards its body to the configured Ollama server without parsing or changing tool messages. It returns the upstream response and appends request, response, status, error, and latency data to a JSONL trace. A0 does not repair, validate, retry, or call a model itself.

**Tech Stack:** Windows CPython 3.11 virtual environment, FastAPI, Uvicorn, HTTPX, pytest.

---

## Files

- `gateway/app.py`: FastAPI application factory and `/api/chat` pass-through endpoint.
- `tests/test_gateway.py`: tests for exact pass-through and trace behavior, plus upstream error handling.
- `requirements.txt`: runtime and test dependencies.
- `logs/trace.jsonl`: generated request trace; ignored by Git.

The existing benchmark at `C:\benchmark` remains unchanged in this milestone. The runner can select the gateway with `OLLAMA_HOST` when the process starts.

## Task 1: prove the pass-through behavior with a failing test

- Create a fake Ollama upstream with `httpx.MockTransport`; do not run a model.
- Send a chat payload containing user, assistant tool-call, and tool-result messages.
- Check that the upstream receives the same JSON, the response status/body are returned, and one trace record is written.
- Run `python -m pytest tests/test_gateway.py -q` and confirm it fails because the gateway behavior is not implemented yet.

## Task 2: implement the smallest pass-through gateway

- Add `create_app(upstream_url, trace_path, transport)` so the endpoint can use a fake upstream in tests and the real local Ollama server when run normally.
- Forward the raw request body to `/api/chat`, use no short timeout that could interrupt model generation, and return the upstream status, body, and content type.
- Append exactly one valid JSON object per request to the trace file, including UTC timestamp, raw request/response text, status, latency, and any error.
- Re-run the focused test and confirm it passes.

## Task 3: verify upstream failure handling

- Add a test that an upstream HTTP error keeps its status and body and is logged.
- Add a test that an unreachable upstream becomes a 502 response and is logged.
- Run the focused tests and confirm all pass.

## Task 4: start A0 locally and check Ollama compatibility

- Start the proxy on `127.0.0.1:8000`, with Ollama as upstream at `127.0.0.1:11434`.
- Point the benchmark client at the proxy with `OLLAMA_HOST` set before Python starts.
- Use development tasks only for the first live check. Holdout prompts stay unused until the gateway and later intervention rules are frozen.

## Scope limits

No parser, detector, repair, retry, streaming, UI, authentication, Docker, or dashboard is part of A0.
